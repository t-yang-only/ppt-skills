# 演示文稿评分基准搭建

## 何时用

- 用户要「搭建 PPT 评分基准 / 评分体系 / 评分标准 / 评分台」
- 用户要「给这个 PPT 打分」「评价这套 PPT 到什么水平」
- 用户问「国赛 PPT 一般多少分」「90 分是什么水平」

## 核心原则

1. **阈值必须有出处** —— 每个量化阈值（页数、字号、色数、文字量）都要来自语料实测分位或官方规则，禁止拍脑袋。
2. **自动 + 人工双轨** —— 能程序化的项自动算（可复算、可回归），审美/叙事类交人工或 judge 判；两轨分值明确分开。
3. **必须有标定表** —— 给出「多少自动分 → 哪一档」，否则 90–99 的说法无法验证。
4. **硬门先于总分** —— 造假/乱码/文字烧图/口径不可溯源等一票项先封顶，再算加权分。

## 五步流程

### 第 1 步：拿官方规则
找赛事的官方评审规则（分值维度 + 必要条件/一票否决项）。这是「内容硬度」维度的唯一依据。
若本地无，用检索台找官方通知原文（不要用二手经验文章替代官方分值）。

### 第 2 步：检索得分规律（定性）
关键词模板：
```
<赛事名> 国赛 金奖 PPT 拆解 得分
<赛事名> 评分标准 得分点 评审
<赛事名> 路演PPT 制作规范 评审标准
国赛金奖PPT 排版 配色 字体 规律
创新创业大赛 PPT 评审 印象分 视觉设计
PPT 评分量规 rubric 版式 一致性 层级
```
优先精读：①官方/高校发布的「路演 PPT 制作逻辑线」类 PDF ②金奖案例拆解长文 ③评分标准附件（.doc/.pdf）。
抽取：得分元素清单、逐页型排版要点、高频失误、网评 vs 现场差异、量化规范（字号/配色/图表）。

### 第 3 步：语料量化取阈值（定量）
找本地已有参考 PPT 语料，两级分析：

**A. 结构级**（若有拆解 CSV）：页数 / 形状数 / 图片数 / 图表数 / 动效页 / 主题色 / 字体 → 出 P25/中位/P75/P90 分位表。

**B. 深度实测**（python-pptx 逐件）：
- 每页字符数（`len(re.sub(r"\s","",text_frame.text))`）
- 每页唯一色数 —— **必须遍历 XML `a:srgbClr` 节点**，`sh.fill.fore_color` / `run.font.color.rgb` 取不到主题色
- 图片面积占比 = Σ(图宽×图高) / (页宽×页高)
- 字号分布 —— **正文基准用 14–31pt 区间的加权中位数**，用全量众数会被页码/脚注带偏
- 画幅比、图表数、表格数、乱码数、引用标注数

**样本清洗（必做，四件事）**：
- **分类打标**：按路径关键词把样本分成「真实作品 / 模板库 / 特效单页 / 纯版式骨架 / 图标素材」，主统计只用「真实作品」类。经验值：一个 399 件的国赛语料里，真正可用的路演作品只有 98 件（1609 页）。
- **剔模板库**：成套模板动辄 300+ 页，页数限 8–45 即可滤掉大部分。
- **纯图片版单列**：脱敏导出的获奖作品文字全烘焙进图（字/页≈0、元素/页=1）。判定式 `字符数≤2 且 图片面积比≥0.8`。混入会拖垮字数与字号分布。
- **前景口径算空白**：面积 ≥85% 的元素视为「背景层」，**不计入覆盖/空白/边距**。否则满版背景会让空白率恒为 0（这是最容易踩的坑，修正前后 0.00 → 0.19–0.29）。

不清洗会导致分位严重失真（实测：字/页中位 186 → 113）。

### 第 3.5 步：元素级全量扫描（推荐做到这一层）
逐页提取并落盘（可断点续跑）：
- 元素清单：类型（txt/pic/shp/cht/tbl/grp）+ 归一化 x,y,w,h + 面积占比 + 字符数
- 空白：64×36 网格并集算前景覆盖率；四边内容边距
- 位置：大元素（面积≥5%）的 24×14 ASCII 热力图 + 中心坐标分位
- 背景：满版图 / 纯色 / 渐变 / 混合（满版图优先判定）
- 色度：srgbClr 集合 + 逐色 HSV（饱和度/明度分位）
- 图片：张数、面积比、满版数、**椭圆裁切数**（人像强信号）
- 语义页：团队页 / 荣誉页关键词标记 + 其图片数分布
- 图表/表格/动效

聚合后出 10 份分布报告（总览/元素构成/位置热力图/字数字号/空白边距/色度/背景/图片人物证书/图表动效/项目对照）。

**元素级再增强（要做「更细致」时的必经一步）**：基础扫描的元素只有 `k/x/y/w/h/a/c`（`c` 是**字符数**不是颜色），颜色仅页级集合。要做到**元素级配色 / 字体 / 字号归属**，必须给扫描器加字段并重扫：
- 元素新增 `fc`（形状填充色，`solid_fill_hex`）、`tc`（主导文字色）、`ft`（主导字体名）、`sz`（主导字号pt）——`text_attrs()` 遍历 runs 取众数。
- 字段是**超集**，旧报告仍可复算；重扫前先 zip 备份原 JSON（`--force` 会就地覆盖）。
- 增强后可多出：元素级填充色/文字色 TOP、按元素类型的色系分工、主色板与集中度（覆盖 80% 元素所需色数）、同色系组内色板 Jaccard 相似度、8×6 细网格内容密度、逐页可见非文字格、**标题字体 vs 正文字体**（按 sz≥24 / ≤18 切分，解决页级字体归属的先天缺陷）。

**再增强（要做「子元素级 + 内容类型」时）**：再加两个字段并重扫——
- 元素 `st` = `spPr/prstGeom@prst`（形状子类型：rect/roundRect/ellipse/line/箭头/三角/flowChart…），用于「版式语言」分析。
- 页级 `文本摘要` = 页面文本前 ~600 字，**内容类型分类的前提**（扫描器默认不存原文！）。
- 产出：形状子类型分布、文本框字号角色（标题≥24/小标题18-23/正文12-17/注释<12）、图片子类型（满版/椭圆/普通）、**内容类型 × 元素分布指纹**（元素数 P25–P75、图片数区间、字号、面积构成）、内容类型判定规则。
- **内容类型指纹是「按页型判分」的基础**：封面=大字号+满版图、团队=多图+椭圆头像、荣誉=证书墙(图≥8)、技术概况=形状面积最高。判分先归类型再比对，而非一刀切。
- 注意：`st=None` 占比通常过半（是**空文本框/自由形状**，无 prstGeom），非取数失败；全样本含模板/骨架（无真实图）会稀释指纹，**指纹一律以主切片为准**。

**三次增强（要做「透明度感知的遮挡」时）**：再给元素加三个透明度字段并重扫——
- `al` = 填充 alpha（`a:solidFill/*/a:alpha@val`，0–100000；无显式填充 None；`noFill` → 0）
- `ia` = 图片 `a:blip/a:alphaModFix@amt`（0–100000）
- `tp` = 图片**透明像素占比**（Pillow 解码，降采样 ≤160px 后统计 alpha<250 的像素；**无 alpha 通道的图直接短路为 0**，避免无谓解码；EMF/WMF 返回 None）
- **遮挡必须按不透明度加权 + 看 z-order**：`op = 填充alpha × 图片alphaModFix × (1−tp)`；扫描器 els 按 spTree 顺序落盘（**索引大者在上**），只有**位于文字之上**的非文字才算遮挡。
- 实测：主切片 **63.2% 的图片带透明区**（tp 中位 0.723），旧 bbox 口径把透明「空面积」当遮挡，**高估 69%**（图压字率 0.086 → 0.027）。旧「非文字未遮挡率」与实际文字可见性**几乎无关**——必须换成透明度感知的「文字可见率」。

### 第 4 步：定维度与硬门
参考权重骨架（可调，示例为 22 子项版本）：

| 维度 | 分值 | 子项 |
| --- | --- | --- |
| D1 叙事结构 | 20 | 页型齐备 10 · 页数合规 4 · 叙事闭环 6(人工) |
| D2 视觉系统 | 22 | 配色克制 6 · 色彩质量 4 · 字体体系 4 · 字号层级 6 · 背景策略 2 |
| D3 布局与信息 | 21 | 元素密度 4 · 文字密度 6 · 图文比 6 · 数据可视化 3 · 空白控制 2 |
| D4 内容硬度 | 25 | 要素覆盖 15 · 数据支撑 6(人工) · 材料真实 4(人工) |
| D5 工程规范 | 12 | 可编辑 4 · 无乱码 3 · 溯源 3 · 画幅 1 · 字体回退 1 |
| 加分项 | +0–3 | 记忆点 / 原型 Demo / 原创视觉体系 |

**硬门**（与总分取最小值）：造假 → 0；文字烧图 → 85；口径不可溯源 → 88；乱码/页数失控/无实拍图 → 89；版权 → 90。

**标定表**（示例，需按自己权重换算；自动 84 / 人工 16 / 加分 3）：
```
目标 95–99 → 自动 ≥76/84 且人工 ≥16
目标 92–94 → 自动 ≥73/84 且人工 ≥15
目标 90–91 → 自动 ≥71/84 且人工 ≥14
```

**新增子项时的「中性再平衡」**：加子项**不要改变自动满分**（否则与历史分不可比）。做法：从相关旧子项各让出等量分。示例：新增 D1.4 页型适配 3 分 ← D1.1 9→7、D1.2 4→3（维度分与自动总分都不变，只增加区分度）。

**内容类型适配（可自动算的页型判分子项）**：逐页先归内容类型（11 类：封面/目录/团队/荣誉/痛点市场/竞品对比/产品方案/技术概况/商业模式/财务股权/未来展望/其他），再按各类型**指纹**判「是否做成该有的样子」——封面 字号≥20 或 满版图；团队 图≥3；荣誉 图≥5；技术概况/痛点市场 形状面积占比≥0.35；财务股权 有图表或形状≥0.35。得分 = 满分 × 达标页数 / 有判据的页数。**这是把「内容类型指纹」落成可复算子项的标准范式**（先归类型再比对，而非全册一刀切）。

### 第 5 步：落成工具 + 实测标定
产出四件：
1. `评分基准_*.md` —— 主基准（权重/硬门/档位/标定/细则）
2. `得分元素与得分排版清单.md` —— 可勾选执行清单
3. `评分器/*.py` —— 自动评分器（输出自动分 + 体检表 + 整改建议 + 人工项清单）+ 批量评分（分维度矩阵）
4. `评分卡/评分卡_模板.md` —— 人工项填写卡

**实测标定**：对 ≥6 件已知水平不同的 PPT 跑一遍，确认
- 区分度：好件确实高于差件
- 硬门灵敏度：纯图片版/乱码件确实被封顶
- 档位合理：参考件落在预期的 90 上下，若全部偏低说明权重过严，需回调

## 坑位速查

| 坑 | 现象 | 解法 |
| --- | --- | --- |
| 色数取不到 | 每页色数恒为 0–1 | 遍历 XML `a:srgbClr`，别用 API 颜色属性 |
| 字号基准偏小 | 正文基准算出 12pt | 限定 14–31pt 取加权中位数 |
| 分位被稀释 | 字/页中位 186 | 清洗模板库/特效/骨架样本 |
| **空白率恒为 0** | 每页空白 0.00，项目件与国赛无法比较 | **前景口径**：面积 ≥85% 的元素视为背景层，不计入覆盖/空白/边距 |
| 纯图片版污染统计 | 字/页 = 0 的件混入 | 单列（`字符数≤2 且 图占比≥0.8`），作为硬门样本 |
| 旧格式读不了 | `.ppt`/`.wps` 报 PackageNotFoundError | 预期行为，跳过并记录 |
| 检索噪声 | 结果里混入维基/百科 | 按查询词与标题/正文重叠度打分过滤 |
| SSL 偶发 EOF | 检索请求随机失败 | 加重试（3–4 次，退避 1.5s） |
| 分数全偏低 | 参考件都不到 90 | 检查人工项是否漏算；自动满分是多少；重算标定表 |
| **对比度不可解** | 算出「61% 低对比」的假象 | 多数文字叠在满版图/渐变上，矢量层无背景色 → 对比度只能对**可解子集**（文字中心处有形状填充色或页面纯色）计算；报告须显式标注**覆盖率**（实测仅 ~9%），不可外推全体 |
| **细网格越界** | 网格总数 > GW×GH 上限 | 元素坐标未钳下界，出血元素（x/y<0）产生负格 → `max(0, min(N-1, int(cx*N)))` 双向钳制，并过滤零面积元素 |
| **可见性恒 0%** | 跨页聚合时「可见非文字格」恒为 0 | 每格都有某页的文字 → 必须**逐页**统计后再取分位，不能跨页聚合 |
| 元素级色系偏黄绿 | 文字色「黄绿」占比异常高 | 金 `#FFC000`(hue45.2)/黄 `#FFFF00`(hue60) 落入「黄绿」边界（橙黄<45）；如需更准可把橙黄边界放宽到 ~52，但要与既有报告口径一致 |
| 中性色口径 | 旧口径把纯黑/纯白并入「红」 | 纯黑/白 s=0 → hue=0 → 归「红」；应改 **s<0.12 判中性**单列，否则红系虚高 |
| 文件级主色系分组出现「中性系」 | 某组页数多但色数中位 0 | 那是**纯图片版 / 全主题色**文件（无显式 srgbClr），非灰色调设计，需在报告里说明 |
| **重叠率口径错** | 评分器算出 0.99 的荒谬重叠 | 必须用 **Σinter/Σunion**（IoU 加权，语料中位 0.0158），**不是** Σinter/Σindividual（那是另一个指标，会得 ~0.99） |
| 色板集中度跨册聚合失真 | 全语料 TOP5 仅 0.19 | 必须**按单册先算、再取中位**（单册中位 0.459）；跨册把所有页的色并起来会失真 |
| 中文字体误判缺失/特殊 | 微软雅黑被标「未嵌入」 | 注册表 Fonts 多为**英文名**（Microsoft YaHei），中文名不在 → 需**中英文白名单**（微软雅黑/宋体/黑体/楷体/仿宋/等线…） |
| **新硬门过苛** | 拟设「特殊字体未嵌入」封顶 90，结果误伤大半真实作品 | 新硬门先在**语料上测触发率**：>30% 就太严（国赛 57.7% 页用特殊字体）→ 降级为扣分项而非硬门 |
| 评分器「判定」列误导 | 字体家族数 6 却标 ✓ | 体检表的 ✓/⚠ 要按指标方向分 **high / low / band** 三种模式，降序指标（家族数/乱码）不能按「≥中位」判 |
| 评分器读主题色件为空 | 某件 TOP5/中性色全 0 | 该件用**主题色（schemeClr）**，元素级 `fill.fore_color.rgb` 取不到 → 色板指标改用**页级 srgbClr 集合**兜底 |
| **分栏数虚高** | 明明是 3 栏卡片，却算出 5–7 栏 | 分栏只聚类**卡片级元素（面积≥5%）**；小图标/标签/标签页会被当成独立列。修正后语料中位仍 3（阈值不变），个别件 5→3 |
| 生成物被脚本覆盖 | 手工加的「评分启示」章节重跑后消失 | 报告里的固定章节必须**写进脚本**（L.append），不要手工 Edit 脚本生成的文件——重跑即覆盖 |
| **遮挡率算错方向** | 新旧遮挡率差值恒为 0 | 若把**两侧**都乘不透明度，比值近似不变 → 无效。必须**只对遮挡方加权**，且加 **z-order**（索引大者在上，非文字在文字之上才算遮挡） |
| **遮挡率与实际不符** | 「未遮挡率」低的件其实文字很清晰 | bbox 口径把**图片透明区**当遮挡。图片中位透明占比可达 0.72、六成图带透明区 → 必须按 `1−tp` 折算，改判「文字可见率」 |
| 图片解码拖慢扫描 | 全量重扫从 300s 涨到 ~690s | 只对 `pic` 算 `tp`；无 alpha 通道（JPEG/RGB）**先判 mode 直接返回 0**，不进入 convert/thumbnail |
| **汇总脚本每轮膨胀** | 参数总表第一次 81 条、第二次 253 条 | 「读汇总 JSON → 汇总 → 再写回同一个 JSON」的脚本，遍历时必须**排除自己写入的节点**，否则自引用累积。写完连跑两次验证结果一致（幂等） |
| 同指标两份报告数字对不上 | 字号角色占比 31.7% vs 36.5% | 分母口径不同（是否含「未设字号」）。新增指标的**分母必须与既有报告写死一致**，并在表下注明分母 |

## 值得报告的「高价值发现」类型

跑完语料统计后，优先找这几类结论（比罗列分位表有用得多）：
1. **默认调色板现象** —— 高频色值里出现 `#FFC000`/`#00B0F0`/`#C00000` 说明样本大量使用 Office 默认主题色 → 自建配色体系即可超基线（低成本高收益）。
2. **动画占比** —— 若「含动效页占比」很低（如 <5%），说明评委侧不看动画，动画是风险而非加分。
3. **目标对象的系统性缺口** —— 把待评对象与语料中位逐项对照，找出「差得最多」的 2–3 项（如字号中位 14pt vs 20pt、图/页 1 vs 6）。这才是评分体系真正交付的价值。

## 第 6 步（可选但价值最高）：整改闭环

把评分结论直接变成工具：
1. **找根因**：每个扣分项，先跑相关变量相关分析（如 字数 vs 字号 → r=-0.296），确认扣分是「症状」还是「根因」再动手。
2. **可机械化部分** → 写整改器（**默认 dry-run**，加 `--apply` 才落盘；**绝不覆盖原件**），自动检测溢出风险后再改。
3. **不可机械部分** → 给出「人工动作清单」（具体页/框 + 删字/换图/重排版）。
4. **渲染对比验证**：用 PowerPoint COM（DispatchEx 独立实例 + Slide.Export 逐页 + PIL 拼并排图）肉眼看版面错位——**分数对但版面可能错位**（典型：芯片固定宽度被字号放大后溢出）。
5. **复评分**：整改后跑同一评分器，给出「自动 X/满分 → Y/满分」的增量 + 上限总分变化（封顶变化说明档位跃迁）。

### 字号整改的硬经验

- **机械天花板 ≈ 17pt**——只提升小字号（<18pt），不动标题，超阈值文本框自动降级为半阶梯。**要到国赛 20pt 必须删字**。
- **必须清 normAutofit.fontScale**——否则 PowerPoint 打开会把新字号缩回原值。
- **溢出启发式用 ratio = 字面积/框面积**（保守上界：n × mx² × 1.15），对**芯片等固定宽度**约束会低估 → 整改报告必须附「人工复核清单」。
- **优先看 render-diff 而不是分对**——P18 团队页芯片溢出就是分数对但版面错的典型。

## PPT 全量导出与复原（可复原级）—— 当需要「拿到原数据就能重建 PPT」时

三层导出，缺一不可：

| 层 | 内容 | 作用 |
| --- | --- | --- |
| `结构.json` | 逐页逐元素全字段 | 可编程重建层 |
| `pkg/` | 原 pptx **全部非媒体条目**，**按原路径**落盘 | 无损层 |
| `media/` | `ppt/media/*` | 素材（唯一外依） |

**关键实现点**：
- `pkg/` 必须**保留原相对路径**（`ppt/slides/slide1.xml`、`ppt/slideLayouts/…`、`[Content_Types].xml`、`docProps/…`）——扁平化改名后拼不回 pptx。重组 = 按原路径写回 zip + 把 `media/*` 放回 `ppt/media/`。
- 结构.json 要含：`z`(z-order) / 类型 / 名称 / 几何 EMU / 旋转翻转 / `prstGeom` / 填充(solid·grad·blip·none + **alpha**) / 描边(色·宽·虚线) / 文本(**段落 + 逐 run**：字号·粗斜下·字体·颜色·行距·段距) / 图片(媒体名·尺寸·**sha1**) / 表格(行列·列宽行高·单元格) / 图表(类型·系列·类别) / **组合递归 children[]**。
- **图片↔媒体用 sha1 匹配**（`image.sha1`），比记 rId 更省事、跨文件稳定。
- 两条复原路径：**A 无损**（pkg/+media/）→ 1:1 100%；**B 结构化**（结构.json+media/）→ 实测几何 99.8%/文本 98.6%（组合需展平、3D 图表会缺）。改造类任务走 B，归档/交付走 A。
- 保真度验证：把两侧组合**展平**后，用 `Counter` 比 `(left,top,width,height)` 与文本的多重集，算命中率。

**python-pptx 兼容坑（必踩）**：
- `pie3DChart` 等 3D 图表：`ch.chart_type` 与 `ch.plots[0]` **都会**抛 `ValueError` → 结构化层落 `raw_xml` 兜底（无损层不受影响）。
- `_Cell` **没有** `width`/`height`（那是列/行的属性）→ 用 `table.columns[i].width` / `table.rows[i].height`。
- `prstGeom` → `MSO_SHAPE` 映射表里**部分枚举名不存在**，构建时必须 `try/except AttributeError`；映射方向别写反（`{prst: getattr(MSO_SHAPE, 枚举名)}`）。
- 给形状注入 alpha 只能改 XML：在 `a:solidFill` 的 `*Clr` 下加 `<a:alpha val="…"/>`。
- 统计容器用 `collections.defaultdict(int)`，否则 `stats["形状失败"] += 1` 会 KeyError。
