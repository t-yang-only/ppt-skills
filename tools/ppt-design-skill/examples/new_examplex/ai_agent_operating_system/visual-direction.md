# Dark Technical Editorial 2.0

## Visual thesis

Treat the agent operating system as a spatial control surface rather than a
collection of agent cards. The deck should feel like a systems editorial: a
dark field, a visible coordinate grid, large plane boundaries, and a small
number of semantic signal colors.

## Direction lock

- Background: deep navy blueprint field.
- Structure: mostly square native panels with colored edge rules; rounded
  containers are reserved for exceptional grouping, not default modules.
- Accent semantics: cyan = intent / routing, amber = control / decision, lime =
  execution / learning, coral = risk / anti-pattern.
- Typography: bold Aptos headlines, restrained monospace metadata and labels.
- Variance: 7/10. Each Agent Pattern receives a distinct spatial composition.
- Motion: 2/10. The static deck must communicate without animation.
- Density: 6/10. Technical diagrams are dense, but whitespace separates planes
  and decisions.

## Transfer decisions from the approved benchmark

- Every page has one dominant visual anchor.
- Components are used as evidence, not decoration.
- Page numbers, source notes, and footer rules remain systematic.
- Technical credibility comes from native editable architecture views and clear
  boundaries, not from extra labels or decorative effects.

## Forbidden patterns

- Repeated rounded-card grids as the default page architecture.
- Decorative connector lines without a semantic relationship.
- Tiny monospace copy used to carry primary meaning.
- More than one competing focal point on a page.
